FoundrAI — System Design

Autonomous AI Advisory Platform for Startup Founders

Backend: FastAPI + Python 3.12 AI: Groq · Llama 3.1 / 3.2 Vision / 3.3-70b RAG: pgvector + sentence-transformers DB: Supabase PostgreSQL 15 Frontend: React 18 + Vite + TailwindCSS Deploy: Render (API) + Vercel (UI) Version: 1.0.0

1 What FoundrAI Does

FoundrAI is a private AI analyst for startup founders. Upload financial data (CSV, Excel, PDF, images), ask natural-language questions about your numbers, run Monte Carlo scenario simulations, and get structured answers backed by your own data, live market news, and four specialist AI agents — all streamed in real time via Server-Sent Events.

Core User Journey

  1. Register / Login

    Supabase Auth issues a JWT. Email + password with optional TOTP MFA. The backend JWT middleware verifies every request and auto-creates a founders profile row on first use.

  2. Upload Financial Document

    CSV, Excel, PDF, DOCX, or image (PNG/JPG). The backend immediately returns an upload_id and processes everything in a background task: Storage → Text extraction (Llama 3.2 Vision for images) → Financial metric parsing → pgvector embedding → financial_rows insertion.

  3. Ask a Question

    The orchestrator fetches the actual CSV rows from the database and passes them directly to Groq. A query classifier routes to: Data (CSV rows + direct synthesis), Web (DuckDuckGo search), or Advisory (4-agent pipeline). Responses stream token-by-token via SSE.

  4. Run a Monte Carlo Simulation

    Bear/Base/Bull scenario + CAC and burn sliders. 10,000 NumPy-vectorized paths run in ~100ms and return P10/P50/P90 revenue bands with runway estimates seeded from the uploaded CSV metrics.

  5. View Charts

    Recharts AreaChart renders the three confidence bands with gradient fills. All simulations are persisted in Supabase for longitudinal comparison.

5.1 Query Classifier

A lightweight Llama 3.1-8b call with max_tokens=4 and temperature=0.0 classifies the question into exactly one route word. Total cost: ~150 tokens.

RouteTriggerContext SourceModelAvg Tokens
dataQuestions about own metrics, revenue, burn, CACDirect CSV rows from financial_rows tableLlama 3.1-8b~900
webMarket benchmarks, industry rates, trends, newsDuckDuckGo top-3 snippets (past 12 months)Llama 3.1-8b~700
advisoryStrategy, fundraising, "how do I grow", decisionsRAG chunks + CSV context → 4 agents → synthesisLlama 3.3-70b~8000

5.2 CSV Context Injection (Key Feature)

This is the mechanism that makes the chatbot "know" what's in your uploaded file without relying only on imprecise vector similarity search.

When a question is asked, _fetch_upload_context() in query.py runs before the LLM. It reads the exact CSV rows from the financial_rows table and passes them as raw data directly to Groq. The LLM can then compute exact totals, averages, and growth rates. 
  _fetch_upload_context(founder_id, upload_id, sb):
    1. If no upload_id → look up founders.active_upload_id
    2. Fetch uploads metadata (filename, columns, row_count)
    3. Query financial_rows WHERE upload_id = ? AND founder_id = ?
       → Returns: month, revenue, burn_rate, headcount, cac, ltv
    4. Format as CSV text: "FILE: finances.csv\nmonth,revenue,...\nJan,50000,..."
    5. Inject into prompt as "FOUNDER'S UPLOADED CSV DATA (exact rows)"

  Non-financial files (PDF, DOCX):
    → Falls back to initial_metrics + columns metadata
    → RAG vector search provides semantic context

6 RAG Pipeline

  ┌─────────────────────────────────────────────────────────────────┐
  │                    RAG INDEXING (on upload)                      │
  └─────────────────────────────────────────────────────────────────┘
  File bytes
      │
      ▼
  extract_text()  ← PDF: pdfplumber  |  DOCX: python-docx
                  ← Excel: openpyxl  |  Image: Llama 3.2 Vision
                  ← CSV: pd.read_csv → column+row text
      │
      ▼
  _chunk_text()   ← 400-token chunks, 80-token overlap
      │
      ▼
  SentenceTransformer.encode()  ← all-MiniLM-L6-v2, 384-dim, normalized
      │
      ▼
  document_embeddings.upsert()  ← Supabase pgvector table
      │  id, founder_id, doc_type, source_filename, chunk_text,
      │  chunk_index, embedding[384], metadata
      │
      ▼
  uploads.update(status="indexed")

  ┌─────────────────────────────────────────────────────────────────┐
  │                   RAG RETRIEVAL (on query)                       │
  └─────────────────────────────────────────────────────────────────┘
  question
      │
      ▼
  SentenceTransformer.encode(question)  → 384-dim query vector
      │
      ▼
  pgvector RPC: match_documents(query_embedding, founder_id, top_k)
      │  cosine_similarity > 0.25 threshold
      │
      ▼
  Also query global_id (00000000-...) for benchmark docs (score > 0.35)
      │
      ▼
  Deduplicate + sort by score → top_k chunks returned

Chunk size: 400 tokens (≈1600 chars) with 80-token (320-char) overlap. Overlap ensures no context is lost at chunk boundaries.

Score thresholds: 0.25 for founder docs, 0.35 for global benchmark docs (stricter to avoid noise).

8 Monte Carlo Simulation Engine

  POST /simulate
      │
      ├─── _fetch_metrics(founder_id, upload_id)
      │       → loads initial_metrics from uploads row
      │       → revenue, burn_rate (fallback to BASE constants if missing)
      │
      └─── run_monte_carlo(months_ahead, growth_scenario, initial_revenue, ...)
               │
               ├─ Scenario multipliers:
               │    bear: revenue_growth=0.02, burn_growth=0.03, volatility=0.08
               │    base: revenue_growth=0.05, burn_growth=0.01, volatility=0.05
               │    bull: revenue_growth=0.10, burn_growth=-0.01, volatility=0.03
               │
               ├─ 10,000 paths × N months — fully vectorised with NumPy
               │    revenue[t] = revenue[t-1] * (1 + growth + noise)
               │    burn[t]    = burn[t-1] * (1 + burn_growth)
               │    cash[t]    = cash[t-1] + revenue[t] - burn[t]
               │
               ├─ P10, P50, P90 = np.percentile(all_paths, [10, 50, 90], axis=0)
               │
               └─ runway_months = months where cash_p50 > 0

Performance: 10K paths for 24 months = 240K float operations. NumPy processes these in a single vectorised call in <200ms on a single CPU core.

  streamQuery(question, upload_id, onEvent)

      ├─ "synthesis_chunk" → append text to streaming message bubble
      ├─ "final"           → seal message, attach agent details, setStreaming(false)
      └─ "error"           → show error bubble

14.1 Deploy Backend to Render

Step 1 — Push code to GitHub

git add .
git commit -m "production ready"
git push origin main

Step 2 — Create a Render Web Service

  1. Go to render.com → New → Web Service
  2. Connect your GitHub repo
  3. Set Name: foundr-ai-api
  4. Set Root Directory: leave blank (repo root)
  5. Set Runtime: Python 3
  6. Set Build Command: pip install -r requirements.txt
  7. Set Start Command: uvicorn backend.main:app --host 0.0.0.0 --port $PORT
  8. Set Instance Type: Free (512MB) or Starter ($7/mo for always-on)

Step 3 — Set Render Environment Variables

In Render dashboard → Environment → Add the following:

KeyValue
SUPABASE_URLhttps://xxxx.supabase.co
SUPABASE_KEYyour-anon-key
SUPABASE_SERVICE_ROLE_KEYyour-service-role-key
SUPABASE_JWT_SECRETyour-jwt-secret (from Supabase → Settings → API)
GROQ_API_KEYgsk_xxxxxxxxxx
ENVIRONMENTproduction
CORS_ORIGINShttps://your-app.vercel.app
LOG_LEVELINFO
NEWSCATCHER_API_KEYoptional — leave blank to skip news

Step 4 — Deploy

Click Create Web Service. Render will:

  1. Clone your repo
  2. Run pip install -r requirements.txt
  3. Start with uvicorn backend.main:app --host 0.0.0.0 --port $PORT
  4. Assign a URL like https://foundr-ai-api.onrender.com
Free tier services spin down after 15 minutes of inactivity and take ~30s to cold-start. Upgrade to Starter ($7/mo) for always-on.

Step 5 — Verify

curl https://foundr-ai-api.onrender.com/health
# Expected: {"status":"ok","version":"1.0.0","environment":"production"}

14.2 Deploy Frontend to Vercel

Step 1 — Add Vercel config (vercel.json)

Create frontend/vercel.json:

{
  "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }]
}

Step 2 — Create Vercel Project

  1. Go to vercel.com → New Project
  2. Import your GitHub repo
  3. Set Framework Preset: Vite
  4. Set Root Directory: frontend
  5. Set Build Command: npm run build
  6. Set Output Directory: dist

Step 3 — Set Vercel Environment Variables

In Vercel dashboard → Settings → Environment Variables:

KeyValue
VITE_API_URLhttps://foundr-ai-api.onrender.com/api
VITE_SUPABASE_URLhttps://xxxx.supabase.co
VITE_SUPABASE_ANON_KEYyour-anon-key (public, safe to expose)
Only VITE_* prefixed variables are exposed to the browser bundle. Never add SERVICE_ROLE_KEY here.

Step 4 — Deploy

Click Deploy. Vercel will run npm run build and publish to a CDN. Every subsequent git push to main auto-deploys.

Step 5 — Update CORS on Render

Once you have the Vercel URL (e.g., https://foundr-ai.vercel.app), update the Render environment variable:

CORS_ORIGINS = https://foundr-ai.vercel.app

Render will automatically redeploy.
